challenge 発動フロー

1. TLS handshake
nginx + ja4 module が ClientHello から JA4 fingerprint を計算 → $client_ja4
2. verdict map
map $effective_ja4 $ja4_verdict { ... } で ok / bot_* / suspect_* に分類
3. final_challenge map
(bv_valid, is_search_bot, is_google_ip, is_known_browser, ja4_verdict, serve_bot_challenge) 6 シグナルで challenge 発動を最終判定
4. challenge HTML 配信
final_challenge=1 の location は internal rewrite で /unmask/challenge/ へ → admin が 403 + sub_filter 済み HTML を返す (= phase=serve ログ)
5. JS 起動
HTML 内 JS が flags / window 等を集めて debug ビーコン送信 (= phase=load)
6. PoW
djb2 hash で 1〜2 秒の計算 → cookie set 試行 (= phase=pow). bot_* verdict なら PoW skip して直接 CAPTCHA
7. CAPTCHA
behavioral checkbox (mouseTrail / clickAt / windowSize / etc) を score 化. 0.5 以上で通過. (= phase=captcha)
8. verify
admin /api/verify が score を確認 → HMAC-SHA1 署名済 _bv cookie 発行 (= phase=verify_ok). 失敗時は verify_ng
9. 通過後
nginx の $unmask_bv_valid 変数 (= ja4 module が cookie を inline 検証) が 1 を返す → final_challenge=0 → 透過パス
